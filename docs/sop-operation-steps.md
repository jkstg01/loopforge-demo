# 配置中心系统（基础版）— 产品方案 SOP 操作步骤

> 本文档记录本项目「配置中心系统（基础版）」采用平台内置「通用产品方案 SOP」（generic-product-delivery）推进时，各阶段的操作步骤与产出，供团队查阅流程与进度。

## 一、SOP 概述

- **流程名称**：通用产品方案 SOP（generic-product-delivery）
- **适用场景**：需求分析、产品方案文档与独立验收；不涉及代码实现，无需代码仓库或 Git Token
- **阶段总数**：5 个（需求定型 → 方案设计 → 独立评审 → 人工验收 → 交付汇总）

## 二、各阶段操作步骤

### 阶段 1：需求定型（clarify）

| 项目 | 内容 |
|---|---|
| 节点类型 | agent（自动执行） |
| 输入 | 需求描述（背景、核心目标、初步功能范围、待澄清决策） |
| 产出 | `requirement.md`（需求定义文档，必填） |
| 操作步骤 | 1. 收敛需求背景与核心目标；2. 明确初步功能范围：命名空间/分组管理、键值配置增删改查、版本历史与回滚、配置发布与生效、审计日志、权限与角色（RBAC）；3. 澄清 5 个关键决策：① 配置值类型（纯 KV / JSON / YAML / 文件型）② 生效方式（实时热更新 vs 重启拉取）③ 敏感信息加密存储方案 ④ 消费端接入方式（API / SDK）⑤ 第一版 MVP 边界；4. 输出 `requirement.md` |
| 流转 | 成功 → 方案设计 |

### 阶段 2：方案设计（design）

| 项目 | 内容 |
|---|---|
| 节点类型 | agent（自动执行） |
| 输入 | `requirement.md` |
| 产出 | `design.md`（产品方案文档，必填） |
| 操作步骤 | 基于需求定义设计产品方案：数据模型、页面/交互形态、技术选型、非功能需求（一致性、可用性、可观测、安全合规）等 |
| 流转 | 成功 → 独立评审 |

### 阶段 3：独立评审（review）

| 项目 | 内容 |
|---|---|
| 节点类型 | agent（自动执行） |
| 输入 | `design.md` |
| 产出 | `review.md`（评审意见，必填） |
| 操作步骤 | 对方案做独立评审，输出评审结论与修改意见 |
| 流转 | 成功 → 人工验收 |

### 阶段 4：人工验收（accept）

| 项目 | 内容 |
|---|---|
| 节点类型 | approval（人工审批节点） |
| 输入 | `review.md` |
| 产出 | 无文件 |
| 操作步骤 | 由运行责任人（madison.wei）在平台确认：**通过** → 进入交付汇总；**拒绝** → 回退到「方案设计」返工 |
| 流转 | 通过 → 交付汇总；拒绝 → 方案设计（返工） |

### 阶段 5：交付汇总（deliver）

| 项目 | 内容 |
|---|---|
| 节点类型 | agent（自动执行） |
| 输入 | 前序各阶段产出 |
| 产出 | `delivery.md`（交付汇总文档，必填） |
| 操作步骤 | 汇总需求定义、产品方案、评审意见与验收结论，形成交付文档 |
| 流转 | 结束 |

## 三、流程流转图

```
需求定型 ──成功──▶ 方案设计 ──成功──▶ 独立评审 ──成功──▶ 人工验收 ──通过──▶ 交付汇总
                                                              ▲
                                                              └──拒绝（回退到方案设计返工）
```
